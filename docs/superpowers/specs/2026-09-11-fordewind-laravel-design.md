# Спецификация Fordewind

## Цель

Собрать Laravel-приложение для попарного голосования за фотографии аукционных автомобилей и просмотра статистики по модели и году выпуска. Окружение должно подниматься через Docker, а работа с AI — быть воспроизводимой по файлам в `docs/agents`.

## Источник требований

Исходное задание: `Task.md`. Кратко оно требует:

- PHP и Laravel, MySQL как основная база.
- Страницу голосования на jQuery: AJAX-загрузка пары, сохранение голоса, увеличение фото через `ezPlus` в режиме Tints.
- Страницу статистики на Vue.js: фильтры по модели и диапазону годов.
- Миграции и воспроизводимый импорт JSON и фотографий.
- Запуск через Docker Compose.
- README и артефакты AI-workflow.

## Бизнес-логика

### Голосование

Пользователь выбирает модель автомобиля. Сервер отдаёт две разные случайные фотографии автомобилей этой модели.

Внутри одного цикла голосования уже показанные фотографии не повторяются, пока не исчерпан доступный набор. Когда в наборе остаётся меньше двух фото, начинается новый цикл.

Пользователь выбирает левую или правую фотографию. Голос сохраняется на сервере. Следующая пара загружается без полной перезагрузки страницы.

Если по модели недостаточно фотографий для пары, страница показывает понятное пустое состояние, а не ломается.

### Статистика

Пользователь фильтрует автомобили по модели и диапазону годов выпуска («от» — «до»). Смена фильтров обновляет список без полной перезагрузки страницы.

Для каждого автомобиля показываются фотография, основные поля исходного JSON и число полученных голосов. Отдельно выводится общее число голосов по текущим фильтрам.

### Импорт

Исходные данные лежат в репозитории <https://gitlab.fdw.ru/ext/test_task>: JSON-описания автомобилей и фотографии. Имя файла фотографии совпадает со значением ключа `Image`.

Импорт идемпотентный: повторный запуск не создаёт дубликаты. Основной надёжный режим — импорт из локального пути. Опционально команда может скачать или обновить GitLab-источник. Секреты для скачивания в репозиторий не коммитятся.

## Архитектура

Laravel 13 как modular monolith. Сначала стандартные механизмы Laravel, затем узкие проектные слои там, где это упрощает границы и тесты.

Основные сервисные единицы:

- `VotingPairService` — выбирает две случайные фотографии выбранной модели с учётом цикла «без повторов».
- `VoteService` — сохраняет победителя и проигравшего на сервере.
- `StatisticsService` — считает голоса с фильтрами по модели и году.
- `CarImportService` — импортирует автомобили и фото из локальных исходников, позже — с опциональным обновлением источника.

HTTP-контроллеры остаются тонкими: валидация, вызов сервиса, Blade или API Resource.

## Модель данных

Планируемые таблицы:

- `cars` — нормализованные поля для фильтров и отображения (`model`, `year` и базовые поля JSON), идентификатор/хеш источника, сырой payload.
- `car_photos` — `car_id`, исходное имя `Image`, стабильный public storage path, checksum/source hash.
- `votes` — идентификатор сессии, `winner_photo_id`, `loser_photo_id`, `winner_car_id`, `loser_car_id`, timestamps.
- `sessions` — таблица Laravel database sessions для серверного состояния цикла голосования.

Состояние цикла хранится в Laravel session по связке `session_id + model`. Для каждой модели держится перемешанная колода оставшихся `photo_id`. Когда в колоде меньше двух фото, начинается новый цикл. Отдельная таблица состояния цикла не нужна.

## Frontend

Страница голосования:

- Blade-layout и отдельный Vite entrypoint.
- jQuery управляет выбором модели, загрузкой пары, отправкой голоса, состояниями loading / disabled / error / empty / success.
- `ezPlus` используется только здесь и только для увеличения фото в режиме Tints.

Страница статистики:

- Blade-layout и отдельный Vue 3 entrypoint.
- Vue управляет фильтрами модели и годов, загрузкой результатов, пустым и ошибочным состояниями, общим числом голосов и таблицей/карточками.
- jQuery на этой странице не используется.

Адаптив:

- Desktop: две фотографии рядом, статистика таблицей.
- Mobile: вертикальное сравнение, доступные кнопки, статистика карточками.

## Harness

Для агентов корневой `AGENTS.md` — инструкция, как работать с репо. Живой этап — `docs/agents/HANDOFF.md`. Для людей достаточно этого spec, `README.md` и `Task.md`.

MCP-конфиги хранятся как шаблоны без секретов. Не коммитить токены, API-ключи, cookies и реальные учётные данные.

## Проверка качества

Минимум перед сдачей:

- Unit-тесты: выбор пары, отсутствие повторов до исчерпания, reset цикла, запись голоса, агрегация статистики.
- Feature-тесты: endpoints голосования, сохранение голоса, фильтры статистики, импорт.
- Сборка Vite.
- Smoke через Docker: поднять сервисы, migrate, import, открыть обе страницы, проголосовать, проверить статистику.
- Проверка README и harness-файлов.
- Проверка diff: нет секретов и реальных credentials.
